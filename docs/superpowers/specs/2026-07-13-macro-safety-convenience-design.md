# MiRi 매크로 안전성 및 편의성 개선 설계

## 목표

자동예약과 빈자리 예약의 안전성을 높이고, 장애를 놓치지 않으면서도 텔레그램 알림이 반복되지 않게 한다. GitHub Pages 설정 화면부터 Oracle Cloud 실행 환경까지 하나의 일관된 설정과 예약 흐름을 사용한다.

## 설정 모델

각 예약 대상에 다음 필드를 추가한다.

- `autoBookEnabled`: 7일 후 자동예약 사용 여부
- `monitorEnabled`: 지정 날짜 빈자리 감시 및 예약 사용 여부
- `weekdays`: 자동예약 대상 요일. 자동예약을 켠 상태에서 비어 있으면 저장할 수 없다.
- `seatPreference.fallbackMode`: `any` 또는 `preferredOnly`

기존 설정은 읽을 때 호환 처리한다. `autoBookEnabled`가 없으면 `weekdays`가 하나 이상인 대상만 활성화한다. `monitorEnabled`가 없으면 `monitorDates`가 하나 이상인 대상만 활성화한다. 기존 좌석 폴백은 `any`로 유지한다.

## 공통 예약 엔진

자동예약과 모니터가 좌석 조회, 좌석 선택, 예약 요청, 결과 해석을 각각 구현하지 않도록 `attemptBooking`으로 통합한다. 엔진은 실제 예약 여부를 나타내는 `dryRun` 옵션을 받고 구조화된 결과를 반환한다.

- 성공: 예약 좌석과 운행 정보 반환
- 이미 예약됨: 성공과 구분되는 완료 상태 반환
- 예약 불가, 좌석 없음, API 오류: 표준화된 사유 코드 반환
- `dryRun`: 좌석까지 선택하되 예약 API를 호출하지 않고 “예약 예정” 결과 반환

좌석 폴백은 `any`이면 선호 좌석이 모두 찼을 때 남은 좌석 중 API 우선순위가 가장 높은 좌석을 선택한다. `preferredOnly`이면 예약하지 않는다.

## 날짜와 설정 검증

모든 날짜 응답은 월별 배열을 `flatMap`해 처리한다. 실행 전에 설정 스키마를 검증하며 이름, 노선 UID, 승하차 UID, 활성화된 자동예약의 요일, 활성화된 모니터의 날짜가 올바르지 않으면 해당 대상을 실행하지 않고 명확한 오류를 반환한다.

설정 UI도 같은 규칙으로 저장을 차단하고 문제가 있는 예약 대상으로 이동한다. 저장 전 요약에는 다음 세 개의 자동예약 대상 날짜, 모니터링 날짜, 좌석 폴백 정책을 표시한다.

## API 안정성

공통 API 요청 계층을 추가한다.

- 기본 제한 시간 15초
- 네트워크 오류와 5xx는 짧은 지수 백오프로 최대 2회 재시도
- 401은 토큰 갱신 후 요청을 1회 다시 수행
- 결과 코드와 HTTP 오류를 표준 오류 객체로 변환

프로세스 진입점은 작업별 잠금 파일을 사용한다. 잠금이 살아 있으면 새 실행은 예약 로직을 수행하지 않고 종료한다. 오래된 잠금은 만료 시간 이후 회수한다.

## 텔레그램 장애 상태

`runtime/state.json`에 장애 상태를 저장하고 저장소에는 커밋하지 않는다.

- 새로운 장애: 즉시 1회 알림
- 같은 장애 반복: 6시간 동안 알림 억제
- 6시간 이상 지속: 누적 횟수를 포함한 요약 알림 1회
- 장애 후 정상 실행: 복구 알림 1회
- 예약 성공과 좌석별 최종 실패는 사건 단위로 알리되 같은 대상·날짜·사유는 6시간 동안 중복 억제
- 매일 오전 9시 이후 첫 정상 모니터 실행에서 일일 상태 요약 1회 전송

텔레그램 HTML 메시지의 동적 값은 모두 이스케이프한다.

## 실행 모드와 Oracle 동기화

패키지 명령을 실제 파일에 맞춘다.

- `npm run autobook`: 7일 후 자동예약
- `npm run monitor`: 지정 날짜 빈자리 감시 및 실제 예약
- `npm run observe`: 모니터와 같은 조회를 수행하되 실제 예약하지 않음
- `npm run update-lines`: 노선 갱신
- `npm test`: 전체 테스트

Oracle용 실행 래퍼는 실행 전 원격 `main`의 `config.json`만 안전하게 가져온다. 동기화 실패 시 기존 설정으로 예약하지 않고 장애 상태로 기록한다. 적용한 원격 커밋 해시는 상태 파일과 일일 텔레그램 요약에 포함한다. 실제 crontab이 새 래퍼를 호출하도록 바꾸는 절차를 운영 문서에 기록한다.

## 설정 UI 편의성

- 대상별 자동예약과 빈자리 예약 토글
- 자동예약의 `매일` 선택 또는 개별 요일 선택
- 좌석 폴백 정책 선택
- 저장 전 실행 미리보기와 검증 오류 표시
- 모니터링 날짜 중 과거 날짜 일괄 정리
- 런타임 완료 상태를 직접 읽을 수 없으므로 예약 성공 날짜는 서버 상태에서 완료 처리하고, UI에서는 과거 날짜 정리와 이미 지난 날짜 저장 방지를 제공
- GitHub 저장 충돌 시 일반 오류 대신 최신 설정 재불러오기 동작 제공
- 변경 사항이 있으면 페이지 이탈 전에 경고

## 파일 구조

- `lib/api-client.js`: 타임아웃, 재시도, 인증 재시도
- `lib/config.js`: 설정 로드, 호환 변환, 검증
- `lib/booking.js`: 공통 예약 엔진과 좌석 정책
- `lib/runtime-state.js`: 잠금, 장애 억제, 복구, 일일 상태
- `lib/telegram.js`: 메시지 이스케이프와 알림 조립
- `auto_book.js`, `monitor.js`, `observe.js`: 얇은 실행 진입점
- `scripts/run-oracle.sh`: 설정 동기화 후 작업 실행
- `docs/index.html`: 설정 편집, 검증, 미리보기, 충돌 복구

기존 `lib/common.js`는 시간과 최소 공통 상수만 남기거나 새 모듈로 역할을 이전한다. `process.exit`는 라이브러리에서 호출하지 않고 진입점에서만 처리한다.

## 테스트

- 빈 요일 대상이 자동예약되지 않는지
- 월 경계의 모니터 날짜를 찾는지
- 두 좌석 폴백 정책이 정확히 동작하는지
- dry-run이 예약 API를 호출하지 않는지
- 타임아웃, 재시도, 401 갱신 경로
- 같은 장애 알림 억제와 복구 알림
- 일일 상태 보고가 하루 한 번만 전송되는지
- 잠금 중 중복 실행이 차단되는지
- 설정 호환 변환과 잘못된 설정 거부
- UI 저장 검증, 미리보기, 과거 날짜 정리, 409 충돌 복구

실제 MiRi 예약 API를 호출하는 테스트는 만들지 않고 의존성 주입과 고정 응답으로 검증한다.
